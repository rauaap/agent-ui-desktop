Session age visibility

Design draft — describes proposed behavior, not an implemented feature.

Behavior

  • A browser-local preference hides sessions inactive for more than N days. The final slider preset, ∞, shows all sessions without a separate toggle.
  • Age is measured from last_active_at, using elapsed 24-hour days.
  • N must be a positive safe integer, independent of the oldest session’s age.
  • A nonempty, case-insensitive search matching a session name overrides the age cutoff. A project-name match does not.
  • Hiding affects only the sidebar: sessions and transcripts remain on the server. An already-open transcript stays open.
  • There is no new API or archive state. The preference is not synchronized across browsers or clients.

Sidebar control

Place one compact horizontal row between the sidebar search box and the sessions list, outside the scrolling project tree. The slider with unlabeled ticks and exact day-count input sit on that same row, with a “days” suffix. The slider flexes to fill available space while the number input stays compact. Explain the session-name search override in a tooltip or accessible description rather than adding another row.

  • The slider uses twelve evenly spaced, unlabeled ticks: 1, 2, 3, 4, 5, 6, 7, 14, 30, 60, 90 days, and ∞. Tapping or dragging it selects that preset, including when the thumb is already there. Exact typed values position the slider at the smallest preset greater than or equal to the value (20 → 30, 45 → 60, 100 → ∞) without changing the cutoff. Typing 100 displays 100; selecting the final tick displays ∞ and shows all sessions.
  • The text input uses a numeric keyboard hint so it can also display ∞; it accepts positive safe-integer day counts. Invalid or temporarily empty number edits do not change the applied value; blur restores the last valid value. Enter commits a valid edit.
  • Both controls remain enabled. The default is ∞. Focusing the input at ∞ clears it for numeric entry; leaving an empty edit restores ∞.
  • Use existing client theme tokens for surfaces, text, borders, accent fill, thumb, and focus rings—not fixed light-theme colors. Give the slider a filled progress track and the number input a compact, matching rounded border.
  • Provide explicit labels, keyboard operation, visible focus, and accessible minimum/maximum/current values. Preserve the number field’s in-progress edit during refreshes.
  • Catalog changes never clamp the cutoff or change the fixed slider range. Existing enabled/day-count preferences retain their meaning.

  Poll --> Catalog["Sidebar.sessions: retain all rows"]
  Controls["Fixed-preset slider and exact day-count input"]

  Controls --> Validate["Validate whole number in range"]
  Validate -->|invalid| Error["Keep applied value; restore field on blur"]
  Validate -->|valid| Save["Persist enabled and N in localStorage"]
  Save --> Apply["Synchronize both controls and render"]
  Storage[("localStorage: session visibility preference")] --> Load["Page initialization: read preference"]
  Load --> Memory
  Save --> Storage
  Apply --> Memory
  Catalog --> Filter["Sidebar.groups: search and age filtering"]
  Memory --> Filter
  Query["Trimmed, lowercase sidebar query"] --> Filter
  Clock["Current time captured once per filtering pass"] --> Filter
  Filter --> Rows["Render visible session rows under their projects"]

The slider range is fixed and independent of the catalog or filtered search results. Slider, numeric input, persistence, and filtering share a single state rather than independently maintained values.

No settings-dialog change, compatibility argument, storage-error suppression, or fallback for malformed catalog timestamps is proposed. An absent preference initializes the filter as disabled.

Per-session visibility decision

  Match -->|no| Hide["Exclude session row"]
  Match -->|yes| Name{"Nonempty query matches session name?"}
  Name -->|yes| Show["Include session row"]
  Name -->|no| Enabled{"Age cutoff enabled?"}
  Enabled -->|no| Show
  Enabled -->|yes| Recent{"last_active_at is at or after
now minus N × 24 hours?"}
  Recent -->|yes| Show
  Recent -->|no| Hide

This preserves existing search matching, but only a session-name match bypasses age filtering. Equality at the cutoff remains visible. Clearing search restores age filtering. Existing project matching and expansion behavior stay unchanged.

Refresh lifecycle

sequenceDiagram
  actor Owner
  participant Controls as Sidebar controls
  participant Storage as localStorage
  participant Sidebar
  participant Server
  Owner->>Controls: Select a slider preset or type an exact cutoff
  Controls->>Controls: Validate and synchronize shared N
  Controls->>Storage: Persist enabled and N
  Controls->>Sidebar: Set cutoff and render
  Owner->>Sidebar: Enter session-name search
  Sidebar->>Sidebar: Include matching old session
  Owner->>Sidebar: Clear search
  Sidebar->>Sidebar: Apply cutoff again
  loop Existing catalog poll
    Server-->>Sidebar: Refreshed complete session catalog
    Sidebar->>Sidebar: Re-evaluate cutoff using current time
  end

When the cutoff is enabled, every catalog poll re-evaluates visibility even if rows have not changed: elapsed time alone can hide a session. Recent activity can bring a hidden session back on the next poll. No additional timer is needed.

Verification cases

  • Infinity initial state, reload persistence, existing preference migration, and all twelve presets.
  • Slider-to-input and input-to-slider synchronization, keyboard controls, theme changes, and tapping the current tick after an exact edit.
  • Reject fractional, zero, negative, and unsafe-integer values; accept exact cutoffs above 90 days without catalog clamping.
  • Exactly at cutoff versus just older than cutoff.
  • Old session revealed by name search, but not by project-only or ID-only search.
  • Clearing search hides old results again; new activity restores them.
  • A poll crossing the cutoff removes a row without requiring catalog changes.
  • Hiding an open session does not close its transcript or modify server data.
